# 検証チェックリスト

手順書を公開する前に、**書いた本人が自分で潰すための一覧**です。

一度きりの点検表ではなく、**次の文書にも使える形**にしています。
[STEP 4 改訂案](./step4-email-proposal.md) への適用結果を、後半に記載しています。

## なぜチェックリストで確認するか

手順書の誤りは、書いているときには見えにくいものです。
書き手は前提を既に知っているため、**抜けた前提に気づけません。**

筆者は、止められないサーバー運用の現場で、**手順書を読む側**を経験しました。
曖昧な一文や抜けた前提が、そのまま作業の停止につながる場面があります。
その経験から、**書き手の記憶ではなく、決まった項目で確認する**ようにしています。

---

## A. 読者と目的

- [ ] 対象読者が**一種類**に決まっているか（複数の読者を一枚に混ぜていないか）
- [ ] 読者が達成したいことが、冒頭に書かれているか
- [ ] 読者が**この文書に来る前に済ませていること**が明示されているか
- [ ] 対象外の読者・対象外の構成が明示されているか

## B. 前提条件

- [ ] 前提条件が、手順より**前**に書かれているか
- [ ] 手順の途中で初めて必要になる情報がないか
- [ ] 必要なものの**入手先・確認方法**が書かれているか
- [ ] 契約プラン・OS・バージョンの範囲が明示されているか

## C. 経路の分岐

- [ ] 読者の状況で手順が変わる場合、**分岐が冒頭にあるか**
- [ ] 分岐の軸が、**提供側の管理単位ではなく読者の目的**になっているか
- [ ] どちらを選べばよいか迷う読者への**推奨**が書かれているか
- [ ] 分岐が排他か併用可かが分かるか

## D. 手順

- [ ] 一つの手順に複数の操作を詰め込んでいないか
- [ ] 操作（何をするか）と説明（なぜそうするか）が分かれているか
- [ ] UIのラベル、コマンド、入力値、出力が**区別できる書式**になっているか
- [ ] 手順が実行順に並んでいるか
- [ ] 例外・トラブル対応が、通常手順から分かれているか

## E. 設定値・参照情報

- [ ] 設定中に参照し続ける情報が、**一箇所にまとまっているか**
- [ ] 値の**出典**（公式ページ・確認日）が記載されているか
- [ ] 間違えやすい値に、注意が添えられているか
- [ ] 複数ページを往復しないと設定できない状態になっていないか

## F. 成功の判定

- [ ] **何ができたら完了か**が明示されているか
- [ ] 判定が、読者自身の操作で確認できるか
- [ ] 一部だけ成功した場合の**切り分け**が示されているか

## G. 失敗したとき

- [ ] 失敗時に戻れる場所が示されているか
- [ ] 症状別に参照先が分かれているか
- [ ] **失敗が目に見えない**種類の事象に、注意があるか

## H. 用語

- [ ] 専門用語に説明があるか、説明ページへの導線があるか
- [ ] 同じものを指す語が、文書内で統一されているか
- [ ] 公式の画面表記と、文書内の表記が一致しているか

## I. 事実の区分 ★この記録群の中核

- [ ] **事実・分析・提案・未確認**が区別されているか
- [ ] 実施していないことを、実施したと書いていないか
- [ ] 確認していない値・画面を、確認したように書いていないか
- [ ] 公式文書を「誤り」と断定していないか
- [ ] 外から見えない理由がある可能性に触れているか
- [ ] 推測で書いて誤った箇所を、**訂正の経緯ごと**残しているか

## J. 出典とリンク

- [ ] 参照した公式ページのURLと**確認日**が記載されているか
- [ ] リンクが現在も有効か（**実際に開いて確認したか**）
- [ ] 開いて確認したリンクと、転記しただけのリンクを区別しているか
- [ ] 公式文書を大量転載していないか
- [ ] 引用に出典が併記され、短い範囲に留まっているか
- [ ] ロゴ・公式画面の画像を無断使用していないか

## K. 秘密情報

- [ ] 会員ID、サービスコード、契約情報が含まれていないか
- [ ] ドメイン名、メールアドレス、IPアドレスが含まれていないか
- [ ] パスワード、秘密鍵、トークンが含まれていないか
- [ ] 現職および取引先の情報が含まれていないか
- [ ] コマンドの実行例やスクリーンショットに、上記が写り込んでいないか

## L. 立場の明示

- [ ] 非公式の文書であることが明示されているか
- [ ] 依頼・許可を受けたものではないと明示されているか
- [ ] 「公式」「監修」「採用された改善案」と誤認させる表現がないか

## M. 第三者による読解（実施できた場合のみ）

- [ ] 技術に詳しくない一人に読んでもらったか
- [ ] 支援なしでどこまで到達できたかを記録したか
- [ ] どの語・どの手順で止まったかを記録したか

> **実施していない場合、「テスト済み」とは書かない。**
> 実施しなかったこと自体を、限界として記載する。

### J：リンクの到達確認（2026年8月15日実施。3本が未確認のまま）

参照している**21本のうち18本**の到達とタイトルを確認しました。

#### 確認できたもの（18本）

| 区分 | 本数 | 結果 |
|---|---|---|
| 診断時に読んだページ | 4 | `2583` / `flow-mail-address` / `mail/2114` / `mail/2869` |

| SPF・DKIM・ウイルスチェック・エラーメール | 4 | 到達。タイトル一致 |

#### 確認できなかったもの（3本）

`faq.sakura.ad.jp` の3本は、**自動取得では本文を読めませんでした。**

| URL | 掲載元での表記 |
|---|---|
| https://faq.sakura.ad.jp/s/article/000001142 | 迷惑メールの対策方法を知りたい |
| https://faq.sakura.ad.jp/s/article/000001143 | メールパスワードがわからない |
| https://faq.sakura.ad.jp/s/article/000001140 | メールソフトで設定、利用時にエラーが表示される |

3本とも、記事本文ではなく
**JavaScriptの読み込みエラーと「よくあるご質問」の文字列のみ**が返りました。

**［未確認］これをリンク切れとは判断しません。**
FAQサイトはJavaScriptで描画される構成のため、
**通常のブラウザでは正常に表示される可能性が高い**と考えられます。
上表の記事名は、STEP 4 のページ上のアンカーテキストからの転記です。

**ブラウザでの目視確認が必要です。**

#### この確認で見つかった自分の誤り（2件・訂正済み）

| 箇所 | 誤り | 訂正 |
|---|---|---|
| `mail/2113` | 「Mac / iOS のかんたん設定」と記載していた | 正しくは「Mac / iOSのメールソフトかんたん設定を利用したい」 |
| `rs.sakura.ad.jp/column/` | 記事名を「POPとIMAPの違い」と記載していた | それは**STEP 4 側のアンカーテキスト**であって、記事名ではなかった |

後者は、**STEP 4 のページ上の表記を、そのままリンク先の記事名として書き写した**ものです。
**リンク先を開いていれば防げた誤り**でした。

なお、この確認により**当該ページがコラム記事である**ことは裏付けられました。
「さくらのホームページ教室」の連載記事で、スタッフによる署名があります。
