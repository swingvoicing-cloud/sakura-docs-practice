# 開発者・運用者へ確認したい点

実際に操作して生じた疑問を、**質問として**整理したものです。

**回答は得ていません。** 推測で答えを埋めず、質問のまま残しています。
それぞれの背景となる観察は [初見利用者としてのつまずき記録](./first-user-friction-log.md) にあります。

設計には、外から見えない理由があります。
ここに並ぶものの多くは「なぜそうなっているのか」を尋ねる質問であって、
変更を求める要望ではありません。

なお、フォームや確認画面に関する質問は**通常モードでの観察**に基づきます。
公式が主経路とするシンプルモードでは検証していません。

---

## まず尋ねたい5件

利用者への影響が大きいと考えた順に並べました。

### 1. 削除時に、ディスクを残した場合の課金継続を案内する方針はありますか

削除画面の「接続されたディスク」の選択は既定でオフです。
チェックせずに削除すると、ディスクが残り課金が継続します。
画面の説明文は「削除する場合は選択してください」であり、
**選択しなかった場合に何が起きるかは書かれていません。**

作成時の確認では「課金対象のリソースを…（料金は作成時より個別に計算されます）」と
課金に言及し、内訳も表示されます。削除時にはその言及がありません。

→ 背景：[つまずき記録008](./first-user-friction-log.md)

### 2. 公式マニュアルの削除手順に、「接続されたディスク」の選択欄の説明が無いのは意図的ですか

画面には選択欄がありますが、マニュアルの削除手順には記載を見つけられませんでした。
**画面のほうが文書より多くを伝えている状態**に見えます。

→ 背景：[つまずき記録008](./first-user-friction-log.md)

### 3. 「費用を止める」目的から引ける導線・文書はありますか

リソースを操作するパネルの左メニューには、課金・料金・請求の項目がありません。
削除した直後に課金の停止を確認しようとすると、別のパネルへ移動する必要があります。

利用者の関心は「サーバを削除する方法」ではなく
「**費用を止める方法**」であることが多いと考えられます。

→ 背景：[つまずき記録009](./first-user-friction-log.md)

### 4. 鍵を保有していない利用者を、公開鍵の入力欄からどこへ導く想定ですか

公開鍵の選択肢は「なし／入力／プロジェクトから選択／github.comのUsernameから取得」で、
既定は「なし」です。4つとも**鍵が既にあることを前提**にしています。

入力形式を誤った際のエラーは「SSH公開鍵として使用できない文字列」で、
**何が不足しているかは示されません**（今回は先頭の `ssh-ed25519 ` が欠けていました）。

→ 背景：[つまずき記録003](./first-user-friction-log.md)

### 5. 登録電話番号が現在使用できない利用者を、エラー画面からどこへ導く想定ですか

電話認証のエラー画面には「電話認証の設定」への導線はありますが、
**登録番号そのものを修正する導線がありません。**
修正先は会員メニューの「会員登録情報の確認・変更 → 住所・連絡先」で、別の階層にあります。

→ 背景：[つまずき記録001](./first-user-friction-log.md)

## その他の質問

### 電話認証

- 電話認証の案内に、携帯電話番号の可否を明記しない理由はありますか
- 音声着信を受けられない利用者向けの代替手段は用意されていますか

### アーカイブの選択

- 同名アーカイブの `(cloudimg)` 有無を、選択画面で区別できるようにしない理由はありますか
- 初期設定の方式（ディスク修正 / cloud-init）が変わることを、選択の時点で示す設計は検討されていますか
- 初見の利用者には、cloudimg と非cloudimg のどちらを推奨する方針ですか
- Ubuntu 24.04 LTS に非cloudimg版が無いのは、意図的な提供方針ですか

### フォームと確認画面（通常モードでの観察）

- 必須項目の表示を「作成数」のみに留めている理由はありますか
- 初見の利用者向けに、既定値のまま作成できる最短経路を示す方針はありますか
- 通常モードとシンプルモードの使い分けは、どこで案内していますか
- 入力形式エラーの文言に、期待する形式を含める方針はありますか
- 一括処理画面とモーダルで同一の文言を用いているのは意図的ですか
- 一括処理画面が「操作待ち」であることを示す表示を加える方針はありますか
- 「内訳を表示」を既定で開いた状態にしない理由はありますか

### 削除の導線

- 削除を行の `▼` メニューに含めていないのは、誤操作防止のためですか
- 「一括削除」という名称は、単一リソースを削除する場合にも適切とお考えですか
- 無効状態のボタンに、無効である理由を示す方針はありますか
- マニュアルの表記「削除」と画面の表記「一括削除」の差は意図的ですか

### 課金の確認

- 当日分の利用料金を、当日中に確認する手段はありますか
- リソース操作のパネルに、課金・請求への導線を置かない設計上の理由はありますか
- 検証・学習目的の短期利用者に、料金アラートの設定を勧める導線はありますか

### サーバの初期状態

- パブリックアーカイブはどの程度の頻度で更新されていますか
  （作成直後のサーバに未適用の更新が126件ありました）
- 「インストールされているパッケージをアップデートする」の既定をオフにしている理由はありますか
- 作成画面で管理ユーザのパスワードを設定する際、それが `sudo` の実行に必要である旨を明示する方針はありますか
- サーバ作成時に生成されるホスト鍵のフィンガープリントを確認する手段はありますか
