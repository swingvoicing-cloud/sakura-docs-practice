# 調査1：さくらのクラウド（実操作）

2026年8月15日、約6時間で、次を一巡しました。

**アカウントの電話認証 → サーバー作成 → SSH公開鍵接続 → Apache導入 →
外部ブラウザからのHTTP到達確認 → サーバーとディスクの削除 → 課金対象の残存確認**

8手順すべて完了。**つまずき9件**を記録しました。

## 最も重要と考えた3件

### 1. 削除時、ディスクを残すと課金が続くが、画面にその説明がない

削除画面の「接続されたディスク」の選択は**既定でオフ**です。
チェックせずに削除するとディスクが残り、課金が継続します。
説明文は「削除する場合は選択してください」であり、
選択しなかった場合に何が起きるかは書かれていません。

作成時の確認画面は課金に言及し内訳も出すのに、削除時には言及がありません。
**費用を止めたい場面でこそ、課金の情報が必要ではないか**というのが所見です。

### 2. 画面が持っている情報が、公式マニュアルに反映されていない

上記の「接続されたディスク」の選択欄について、
公式マニュアルの削除手順に記載を見つけられませんでした。
**画面のほうが文書より多くを伝えている状態**です。

### 3. 「サーバを消す」導線はあるが、「費用を止める」導線がない

リソースを操作するパネルに、課金・請求への導線がありません。
削除の直後に課金の停止を確認しようとすると、別のパネルへ移動します。
利用者の関心は「削除の手順」ではなく「費用を止めること」であることが多いはずです。

**3件とも、追加開発ではなく文書で解決できる**と考えています。

公式マニュアルは「デフォルトの状態では…シンプルモードが選択されています」と記しており、
シンプルモードで試せば解消される所見が含まれる可能性があります。

# 調査2：スタートアップガイド STEP 4「メールを設定する」（読解・試作）

レンタルサーバの「初めてでも安心！スタートアップガイド」STEP 4 を診断し、
**一枚に畳んだ改訂版を試作**しました。

**［重要］この調査は、現時点では公開ページの読解に基づきます。**
コントロールパネルの画面名も、設定値での接続も、**実機で確認していません。**
したがって、これは検証済みの手順書ではなく、**改善仮説と試作**です。

## 最も重要と考えた3件

### 1. さくら自身が「推奨できかねる」としているソフトへ、入口が誘導し得る

「Outlook(new)の設定をしたい」のページには、
**サーバーにメールが届いていても受信できない現象が確認されているため、
現時点では利用を推奨できかねる**旨が記載されています（2026年8月15日確認）。

一方 STEP 4-2 の本文には、**ソフト選択に関する注意が見当たりませんでした。**
Windows 11 では新しいOutlookが標準のメールアプリとして提供されているため、
案内どおりに進んだ利用者が、そのソフトへ到達し得ると考えました。

この事象は、**設定の失敗としては現れません。**
設定は完了したように見えて、メールだけが届きません。

**さくらはこの不具合を隠していません。**現象も制限も代替案も、ソフト別ページに書いてあります。
**情報は既にある。問題は在処であって、内容ではありません。**

### 2. ウェブメールという経路が、入口から辿れない

ウェブメールは公式に提供され、**3本の記事で文書化**されています。
しかし STEP 4 からも、STEP 4-1 が案内する「作成・設定フロー」からも、
**言及を見つけられませんでした。**

STEP 4 は「アドレス作成 → メールソフトの設定 → その他の設定」の一直線で、
**どこで読むかを選ぶ分岐がありません。**

**★ただし、さくら自身はウェブメールを使っています。**
メールソフトのトラブルに関するFAQには、切り分けの**最初の手順**として
「まず、ウェブメールにログイン可能かお試しください」と書かれています。

つまり**ウェブメールは、既にさくらの切り分け手順の基準点になっている。**
**それを利用者が知るのは、詰まってFAQに辿り着いた後です。**

改訂案がウェブメールを冒頭に置くのは、新しい発想ではありません。
**さくら自身の手順を、詰まる前に移すだけ**です。

### 3. 一つの目的に対して、情報が3つのホスト・6つの棚に散っている

STEP 4 とその周辺から辿れるリンクは**17本**あり、行き先は
ヘルプの `mail/`・`domain/`・`rs/`・`flow-mail-address/`、別サイトのFAQ（6本）、
そして**コラム記事**に分かれていました。

特に、設定中に参照し続ける**設定値**が本文と別ページにあります。

**3件とも、追加開発ではなく文書で解決できる**と考えています。

**調査1の所見2と、調査2の所見1・2は同じ形をしています。**
**画面や個別ページのほうが、入口の文書より多くを伝えている**という形です。

## この文書の作法

- 感想ではなく、**再現できる観察**として書く
- **事実・分析・未確認・質問**を分ける
- 公式文書を「誤り」と断定しない。観測した事実と、確認したい質問に分ける
- 実施していないことを、実施したとは書かない
- 良かった点も同じ密度で書く

推測から書いて誤った箇所は、**訂正の経緯ごと残しています**（記録002と004）。
いずれも「片側の文書だけを読んで結論を出した」ことが原因でした。
検出して直せることも、記録の一部と考えています。

## これは何ではないか

- さくらインターネット株式会社の公式文書ではなく、同社の見解を代表するものでもありません
- 同社から依頼・許可を受けて作成したものではありません
- 公式文書の誤りを指摘する目的で作成したものではありません
- STEP 4 改訂案は、採用された改善案ではありません
